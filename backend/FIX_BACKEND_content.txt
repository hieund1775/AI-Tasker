Tài liệu này bao gồm **3 phần sửa đổi cốt lõi**:1. **Sửa lỗi Submit Task**: Nhận & Lưu thông tin sản phẩm (Link/File) của Expert.2. **Sửa lỗi Phân Quyền & Báo Cáo (Dispute/Report)**: Mở khóa quyền cho Admin và mở rộng DTO nhận đầy đủ các trường báo cáo chi tiết.3. **Đề xuất làm sạch Database Dự án (Tùy chọn)**: Bổ sung cột lưu sản phẩm và lý do từ chối cuối cùng của dự án để thay thế cho giải pháp gộp JSON tạm thời của Frontend.Đại ca gửi toàn bộ nội dung dưới đây cho Backend nhé:---# 📝 TÀI LIỆU YÊU CẦU CHỈNH SỬA & ĐỒNG BỘ BACKEND (AI-TASKER)Chào ông, để hệ thống chạy trơn tru các luồng: (1) nộp và phê duyệt sản phẩm của từng Task, (2) hủy hợp đồng và gửi báo cáo vi phạm lên Admin xét duyệt, ông cập nhật giúp tôi các file Backend theo đặc tả kỹ thuật chi tiết dưới đây nhé:---## PHẦN 1: LƯU THÔNG TIN SẢN PHẨM KHI EXPERT SUBMIT TASK**Vấn đề**: Hiện tại API nộp bài của Task (`POST /api/Projects/tasks/{taskId}/submit`) đang bỏ qua không nhận Request Body và không cập nhật trường `Notes` (chứa link/file sản phẩm nộp từ expert) vào Database.### 1. Cập nhật DTO `SubmitTaskDto.cs`Đảm bảo class DTO này nằm trong thư mục DTOs của dự án và có thuộc tính `Notes`:```csharp// File: backend/API/Modules/ProjectModule/DTOs/SubmitTaskDto.csnamespace AITasker_Modular.Modules.ProjectModule.DTOs;public class SubmitTaskDto{    public string? Notes { get; set; }}```### 2. Cập nhật `ProjectsController.cs`Sửa endpoint nộp bài của Task để nhận dữ liệu từ body và truyền xuống Service:```csharp// File: backend/API/Modules/ProjectModule/ProjectsController.cs[HttpPost("tasks/{taskId:guid}/submit")]public async Task<IActionResult> SubmitTaskForReview(Guid taskId, [FromBody] SubmitTaskDto dto){    try    {        var result = await _projectService.SubmitTaskForReviewAsync(taskId, dto?.Notes);        if (result == null) return NotFound("Không tìm thấy tác vụ tương ứng.");        return Ok(result);    }    catch (Exception ex)    {        return StatusCode(500, ex.Message);    }}```### 3. Cập nhật Interface `IProjectService.cs`Cập nhật chữ ký hàm nhận thêm tham số `notes`:```csharp// File: backend/API/Modules/ProjectModule/IProjectService.csTask<ProjectTask?> SubmitTaskForReviewAsync(Guid taskId, string? notes);```### 4. Cập nhật Logic trong `ProjectService.cs`Gán giá trị `notes` nhận được vào thuộc tính `Notes` của `ProjectTask` trước khi lưu xuống Database:```csharp// File: backend/API/Modules/ProjectModule/ProjectService.cspublic async Task<ProjectTask?> SubmitTaskForReviewAsync(Guid taskId, string? notes){    var task = await _context.ProjectTasks.FirstOrDefaultAsync(t => t.Id == taskId);    if (task == null) return null;        task.Status = "Pending Approval";    task.Notes = notes; // CẬP NHẬT: Lưu chuỗi JSON chứa sản phẩm nộp từ expert    task.UpdatedAt = DateTime.UtcNow;        await _context.SaveChangesAsync();    return task;}```---## PHẦN 2: MỞ KHÓA QUYỀN ADMIN & MỞ RỘNG BÁO CÁO VI PHẠM (DISPUTE/REPORT)### 1. Cho phép tài khoản Admin truy cập các API của Staff**Vấn đề**: Hiện tại các hàm kiểm tra quyền xử lý tranh chấp trong `DisputeService.cs` đang chặn cứng chỉ cho người dùng có Role là `"staff"` truy cập, tài khoản quản trị tối cao `"admin"` hệ thống bị báo lỗi `403 Forbidden`.**Giải pháp**: Cập nhật file `DisputeService.cs` để cho phép cả Role `"staff"` và `"admin"` xử lý:```csharp// File: backend/API/Modules/DisputeModule/DisputeService.cs// 1. Tại hàm TriggerProjectDisputeLockAsync:var staff = await _context.Users.AnyAsync(x => x.Id == staffId && (x.Role.ToLower() == "staff" || x.Role.ToLower() == "admin") && x.Status == "Active");// 3. Tại hàm ExecuteDisputeVerdictAsync:var staff = await _context.Users.AnyAsync(x => x.Id == staffId && (x.Role.ToLower() == "staff" || x.Role.ToLower() == "admin") && x.Status == "Active");```### 2. Mở rộng DTO gửi báo cáo vi phạm (`SubmitReportInputDto`)**Vấn đề**: API gửi báo cáo (`POST /api/Dispute/user/submit-report`) nhận DTO quá thiếu trường và bị đánh dấu `additionalProperties: false`, khiến Frontend khi truyền đầy đủ thông tin báo cáo lên sẽ bị lỗi `400 Bad Request`.**Giải pháp**: Bổ sung đầy đủ các trường mô tả tranh chấp vào DTO để lưu đúng vào thực thể `Report` trong DB:```csharp// File: backend/API/Modules/DisputeModule/DisputeController.cspublic class SubmitReportInputDto {     public Guid ProjectId { get; set; }     public Guid ReporterId { get; set; }     public string Reason { get; set; } = string.Empty;     public string? EvidenceUrl { get; set; }         // BỔ SUNG CÁC TRƯỜNG DƯỚI ĐÂY ĐỂ ĐỒNG BỘ GIAO DIỆN:    public string? ReporterRole { get; set; }    public string? ReportType { get; set; }    public string? Description { get; set; }    public string? DisputeType { get; set; }    public string? DesiredResolution { get; set; }}```### 3. Cập nhật Logic lưu trữ báo cáo vi phạmSửa lại Signature hàm trong `IDisputeService.cs` và cập nhật logic lưu trữ tương ứng trong `DisputeService.cs`:```csharp// File: backend/API/Modules/DisputeModule/DisputeService.cspublic async Task<Guid> SubmitProjectReportAsync(    Guid projectId,     Guid reporterId,     string reason,     string? evidenceUrl,    string? reporterRole = null,    string? reportType = null,    string? description = null,    string? disputeType = null,    string? desiredResolution = null){    var projectExists = await _context.Projects.AnyAsync(x => x.Id == projectId);    if (!projectExists) throw new KeyNotFoundException("Không tìm thấy dự án tương ứng để khiếu nại.");    var report = new Report    {        Id = Guid.NewGuid(),        ProjectId = projectId,        ReporterId = reporterId,        Reason = reason,        EvidenceUrl = evidenceUrl,        CreatedAt = DateTime.UtcNow,        Status = "Pending",        HandlerStaffId = null,                // GÁN CÁC THÔNG TIN MỚI:        ReporterRole = reporterRole,        ReportType = reportType,        Description = description,        DisputeType = disputeType,        DesiredResolution = desiredResolution    };    _context.Reports.Add(report);    await _context.SaveChangesAsync();    return report.Id;}```---## PHẦN 3: BỔ SUNG CỘT CHO BẢNG DỰ ÁN (PROJECT) ĐỂ HỖ TRỢ PHÊ DUYỆT SẢN PHẨM TỔNG (Tùy chọn nâng cấp)**Vấn đề**: Hiện tại thực thể `Project` chỉ có một cột duy nhất là `ProjectLink` để lưu sản phẩm nộp, dẫn đến việc không thể lưu file đính kèm sản phẩm tổng hoặc lý do từ chối (Decline Reason) từ Client một cách độc lập.
